# UProcMapGenerator

> `Source/CrazyArcade3D/MapGen/ProcMapGenerator.h/.cpp` · UObject + IMapGenerator

절차 맵 생성기. 산·협곡 Z6층(웨딩케이크 계단식 — 전 층 1칸 점프 도달), 인원별 크기 티어.
리롤 루프: 생성 → 검증(`FMapValidator`) → 불통과면 파생 시드로 재시도.

## 역할

- 시드에서 **플레이 가능한 절차 지형을 생성**한다: 외벽 → 계단식 구조물 → 평지 채움 →
  스폰 배치 → 아이템 배치.
- 생성 결과를 `FMapValidator`로 검증하고, 불통과면 파생 시드로 리롤 — 통과한 맵만 내보낸다.
- 서버와 클라 양쪽에서 같은 입력으로 실행돼 같은 맵을 만든다.

## 왜 이렇게 했는가

- **왜 리롤 구조인가** — "항상 유효한 맵을 직접 구성"하는 알고리즘은 어렵고,
  "빠르게 생성 + 검증 + 재시도"는 쉽고 예측 가능하다. 상한(`ProcRerollMaxAttempts`) 초과 시
  폴백 생성기로 넘어가므로 무한 루프 위험도 없다.
- **리롤 시드가 `Seed*7919+attempt` 고정식인 이유** — 리롤도 결정론이어야 한다.
  서버가 3번째 시도에서 성공했으면 클라도 정확히 3번째 시도에서 같은 맵을 얻어야 한다.
  (7919는 소수 — 시드 간 상관을 줄이는 관례적 선택.)
- **난수는 `FRandomStream` 하나, 단계 순서 = 난수 소비 순서 = 계약** — 단계(외벽 → 구조물 →
  평지 → 스캐터 → 스폰 → 아이템)의 순서를 바꾸면 같은 시드에서 다른 맵이 나온다.
  주석에 계약으로 명시.
- **왜 웨딩케이크(계단식) 구조물인가** — 확정된 이동 규칙이 "1칸은 오르고 2칸은 못 오름"이다.
  전 층이 1칸 계단으로 연결돼야 검증 ①(연결성)을 구조적으로 통과한다.
- **파괴:고정 8:2 (구조물 전체 Destructible)** — 사용자 확정(2026-08-06). Immortal은
  외곽 벽 + 기둥 격자뿐. 지형이 매치 후반에 실제로 무너져 내리는 게임의 정체성.
- **크기 인원별 티어(≤4명 17×17, 초과 21×21)** — 인원 대비 맵이 크면 조우가 안 일어난다.
  값은 룰셋, 판정은 서버, 결과(`GridSize`)는 복제.
- **아이템 배치는 `FMapGenUtil` 공용 본체** — 폴백과 같은 함수. 폴백으로 떨어진 판만
  아이템 규칙이 달라지는 것을 방지.
