# 역할

너는 10년차 언리얼 게임 개발자야.

## 배경

`mds/crazy-arcade-3d-architecture.md`, 'crazy-arcade-3d-gdd-v2.md' 에 시스템 기획서와 구조가 작성돼 있어.

## 요구사항

- 의 각 클래스를 task 단위로 분리해서 `mds/Tasks/` 폴더에 MD 파일로 만들어줘.
  - 생성할 클래스의 구조(클래스명, 부모 클래스, 역할)
  - 검증원칙
  - 응답원칙
  - 클래스와 함수에는 어떤 역할을 하는지 설명을 위한 **주석** 포함
- 각 task에 대응하는 검증 체크리스트를 `mds/Checklists` 폴더에 MD 파일로 만들어줘.


### task 분해 원칙

- 반드시 `1 task = 1 class` 원칙을 유지해줘.
- 클래스 책임은 유지하되, task 번호는 기술 명세의 코드 나열 순서가 아니라 작업 순서 기준으로 정해줘.
- 각 task는 하나씩 구현하고 테스트한 뒤 다음 task로 넘어갈 수 있도록, 앞 task의 결과가 다음 task의 구성과 연결로 자연스럽게 이어져야 해.

#### 구현흐름

- 캐릭터 표시 및 동작 구현
- 실시간 데이터 연동 (날씨/어획 판정)
- 사용자 인터랙션 (판매/보관 선택)
- 결과 반영 및 부가 기능

### 작성 기준

- 모든 task 파일에는 구현 순서 번호를 붙여줘.
- 각 task 문서는 개발자가 바로 구현할 수 있게 작성해줘.
- 각 checklist는 실제 검증 가능한 항목 중심으로 작성해줘.
- Play Mode를 실제로 돌리지 않은 항목은 반드시 미검증으로 남겨줘.
