# Task 27 — DeathHandling (사망 처리·관전)

> 선행: Task 12(StatusComponent), 18(승패 판정) · 후행: Task 26(결과 화면), 부활 기능(미정)
> 체크리스트: `mds/Checklists/27-DeathHandling.md`
>
> ⚠️ **1 Task = 1 Class 관례의 예외** — 새 클래스를 만들지 않고 기존 `UStatusComponent`·
> `ACA3DCharacter` 를 확장한다. 번호 27 은 "나중에 추가됨"이라는 뜻이고, 실제 작업 순서는
> `mds/tasks.md` 의 2주차 목록 위치를 따른다 (Task 18 직후, Windows 데디 확인 이전).

## 왜 지금 하나

Task 18 로 승패 판정은 끝났지만 **죽어도 화면에서 아무 일이 일어나지 않는다.** 시체가 그대로 서 있고,
움직이고, 산 사람의 길을 막는다. GDD 의 "사망자가 관전 상태로 남고 매치는 계속 (유령 방해 없음)"이
지켜지지 않으므로 8인 한 판 완주 테스트(2주차 목표)가 성립하지 않는다.

## 설계 결정

### 폰을 유지한다 — 파괴·풀링 아님

| 선택지 | 판단 |
|---|---|
| **폰 유지 + 상태만 전환** ← 채택 | 되돌리기가 가장 싸다(부활 = 상태 복구). 카메라(폰의 SpringArm)가 그대로라 관전 시점 재배선이 0줄 |
| 폰 파괴 | ViewTarget 이 사라져 관전 카메라 액터·재배선이 필요하고, 부활 시 재스폰까지 붙는다. 3주 프로젝트에 비용이 크다 |
| 풀 반납 | **프로젝트 규칙 위반** — `CLAUDE.md`: "풀링은 클라 시각 요소만. 서버 권한 상태를 가진 액터는 풀링하지 않는다(재사용 시 상태 오염 위험)". 캐릭터는 스탯·생존 상태를 가진다 |

### `ELifeState::Spectating` 은 이번에 쓰지 않는다

enum 에 값이 있지만 **`Dead` 하나로 처리한다.** 상태를 둘로 나누면 지금 있는 모든 `== Dead` 가드를
두 곳으로 늘려야 하는데 그만한 이득이 없다. 관전 전용 동작(자유 시점 이동·다른 플레이어 추적)이
생기거나 부활이 들어와 "죽음"과 "관전"을 구분해야 할 때 도입한다.

### 사망 시 적용할 것

| 항목 | 주체 | 이유 |
|---|---|---|
| 이동 입력 무시 | 서버·클라 공통 (`ACA3DCharacter::Move`/`DoJump` 최상단) | 컨트롤러가 아니라 캐릭터에서 막아야 봇(Task 20)도 같은 경로를 탄다. **두 함수의 조건이 다르다** — `Move` 는 `Dead` 만 막고, `DoJump` 는 `Alive` 가 아니면 전부 막는다(갇힘 포함, 2026-08-02 확정) |
| `MovementMode = MOVE_None` | **서버·클라 각자 적용** (아래 정정 참조) | 컬리전을 끄면 바닥을 뚫고 떨어진다. 카메라가 폰에 붙어 있어 시체가 낙하하면 관전 시점도 같이 떨어진다 |
| 캡슐 컬리전 off | **서버·클라 각자 적용** (아래 정정 참조) | GDD "유령 방해 없음" — 시체가 산 사람의 길을 막으면 안 된다 |
| **액터 숨김** (`SetActorHiddenInGame`) | 클라 (`OnRep_Life`) | 시각 전용 (불변식 5). 데디 서버에서는 실행되지 않아야 한다. ⚠️ 스켈레탈 메시(`GetMesh`)만 끄면 **BP 서브클래스가 추가한 메시가 남는다** — 2026-07-30 PIE 에서 실제로 시체가 계속 보였다. 액터 단위로 끄면 코드가 "무엇이 보이는 컴포넌트인지"를 알 필요가 없다. 카메라는 영향 없음(숨김은 프리미티브 렌더링만 막고 ViewTarget 자격·시점 계산과 무관) |
| 폭탄 설치 거부 | 이미 구현됨 (`ServerPlaceBomb` 의 Alive 검증) | 회귀만 확인 |

> **정정 (2026-07-30, 구현 중 발견)**: 위 두 항목을 처음에 "서버 (복제됨)"으로 적었는데 **틀렸다.**
> 엔진 소스로 확인한 사실:
> - `SetCollisionEnabled` 는 컴포넌트 프로퍼티라 **애초에 복제되지 않는다** (`AActor::bActorEnableCollision` 도 복제 등록 없음).
> - `ACharacter::ReplicatedMovementMode` 는 **`COND_SimulatedOnly`** (`Character.cpp:2148`) —
>   즉 **정작 죽은 본인(AutonomousProxy)에게는 오지 않는다.**
>
> 그래서 서버 가드로 감싸면 ① 죽은 플레이어 자기 화면에서만 시체가 바닥을 뚫고 떨어지며 카메라가
> 따라 내려가고, ② 다른 클라에서는 시체 캡슐이 계속 길을 막는 버그가 난다. 두 값은 서버·클라가
> **각자 적용**한다. 권위는 여전히 서버의 `LifeState` 하나뿐이고 클라는 그 복제 결과를 반영할 뿐이라
> 불변식 5 를 어기지 않는다 — CMC 값을 서버·클라가 같은 경로로 계산하는 `RefreshMoveSpeed` 와 같은 관례다.

카메라는 죽은 자리에 그대로 둔다. 자유 관전·다른 플레이어 추적은 후속(필요해지면).

### 부활을 넣게 되면 되돌릴 것 (문서화만, 구현 안 함)

`LifeState` · 캡슐 컬리전 · `MovementMode` · 메시 가시성 · `ACA3DPlayerState::bAlive`/`FinalRank` ·
`ACA3DGameState::AliveCount`. 이 목록이 한 곳(`ApplyDeathState`)에 모여 있어야 되돌리기가 쉽다 —
그래서 사망 처리를 여기저기 흩지 말고 **함수 하나에 모은다.**

- `Tests/StatusComponentTests.cpp` 또는 신규 — 검증

## 검증 원칙

- 공통 원칙 + 아래.
- 자동화: 사망 후 `Move`/`DoJump` 가 위치·속도를 바꾸지 않는가, 컬리전·이동 모드가 꺼졌는가,
  중복 `ServerKill` 이 무시되는가, 폭탄 설치가 거부되는가.
- PIE(Listen + 클라 1 이상): 죽은 캐릭터가 사라지고, 산 사람이 그 자리를 **통과**할 수 있고,
  죽은 클라의 화면이 그 자리에서 매치를 계속 보여주는가. 데디 서버 로그에 시각 처리가 없는가.

## 응답 원칙

- 공통 원칙.
- "이동 불가"를 어디서 막았는지(캐릭터인지 컨트롤러인지) 명시한다 — 봇이 같은 경로를 타는지가 갈린다.
- 관전 카메라 정책(그 자리 고정)을 바꿨다면 이유와 함께 보고한다.
