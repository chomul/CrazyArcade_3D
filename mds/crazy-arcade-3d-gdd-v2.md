## 0. 한 줄 요약

마인크래프트식 복셀 그리드 위에서 벌어지는 3D 크레이지 아케이드.
**공중은 안전지대가 아니고, 발판만이 안전하다.** 폭발이 지형을 실시간으로 무너뜨리고, 무너진 바닥은 곧 죽음이다.

## 2. 코어 게임플레이 규칙 (확정)

### 2.1 공간과 이동
- **완전 3D** — 높이 개념 포함, 다층 맵
- **그리드 유지** — 이동은 자유, 폭탄 설치·폭발·블록 판정은 정수 그리드
- **층간 이동은 점프만** — 1블록 높이 오르기. 점프대·사다리 없음
  - ⚠️ 맵 생성기가 **계단식 접근로를 반드시 보장**해야 함
- **낙사** — 맵 아래는 허공. 떨어지면 즉사
  - (v2 아이디어) 최하층이 존재하되 점점 좁아지는 특수 맵

### 2.2 폭발
- **6방향 전파** — 십자(±X, ±Y) + 수직(±Z)
- **연쇄 폭발 있음** — 물줄기가 다른 폭탄에 닿으면 유발. 층간 연쇄 발생
- **폭탄 타이머 3초** (튜닝 가능 값)
- **물줄기 잔존 1초** — 길목 봉쇄 전술 유지. 위층에서 쏟아지는 물이 아래층 통로를 막음
- **위험 구역 프리뷰** — 폭발 예정 범위를 바닥·벽 데칼로 사전 표시 (3D 카메라 직관성 보완, 초반부터 필수)

### 2.3 생존과 사망
- **"발판만이 안전하다"** — 점프로 다른 발판에 올라가면 회피 성공. 제자리 점프(공중 체류)로는 못 피하고 사망
- **갇힘 유지** — 피격 시 즉사가 아니라 물방울에 갇힘
  - **자력 탈출 불가** — 니들 아이템으로만 탈출
  - 갇힌 상태에서 아주 조금씩 이동 가능 (원작 감성)
  - 권장 지속 시간: 3~5초 (구출 개념이 없으므로 짧게)
- **사망 후 관전만** (유령 방해 없음)

### 2.4 매치
- 라스트맨 스탠딩 / **단판제**
- 최소 2명부터 시작 가능 (테스트 시 봇으로 채움)
- **서든데스** — 하늘에서 물폭탄 랜덤 낙하 → 블록 파괴 → 구멍 → 낙사로 자연 축소
  - 낙하 지점 **1~2초 사전 예고**(그림자/마커) 필수
  - **외곽 낙하 확률 가중** → 플레이어가 중앙으로 몰림
  - 권장 발동 시점: 2~3분 (매치 총 3~5분 목표)

## 4. 맵

### 4.1 구성
- **블록 3종**: 불멸 / 파괴 가능 / 바닥
  - 바닥 파괴 가능 여부는 **플레이테스트로 결정** → bool 설정값으로 노출
- 지형: 평지뿐 아니라 산·협곡 형태 생성 가능
- 규모: 15×15×3 또는 21×21×4에서 시작 → 테스트하며 확대

### 4.2 생성 (규칙 기반 절차 생성)
**시드 기반 결정론적 생성** — 서버가 시드 4바이트만 보내면 클라가 동일 맵 생성
- 부동소수점 대신 정수 연산, `FRandomStream`으로 랜덤 고정

**검증 로직을 순수 함수로 분리** — 유효하지 않으면 리롤
- [ ] 모든 층이 점프로 도달 가능한가
- [ ] 8개 스폰 간 최소 거리 확보
- [ ] 스폰 주변 탈출로 2방향 이상
- [ ] 고립된 빈 구역 없음
- [ ] 아이템 배치 균등도

**안전장치**
1. 손으로 만든 폴백 맵 1개를 먼저 제작 (1주차 코어 검증용)
2. 시드 고정 기능 → 버그 재현·테스트 가능
3. 생성기 완성도가 낮아도 게임은 돌아가야 함

## 6. 네트워크 설계

### 6.1 권한 구조
- **완전 서버 권한 + 클라이언트 예측**
- 이동: `CharacterMovementComponent` 활용 (예측·보정·리플레이 무료로 획득)
- **폭탄 설치도 로컬 예측** — 즉시 표시 → 서버 확인 시 교체
  - ⚠️ 예측 폭탄은 **시각 전용 액터**로만 구현. 타이머·판정·연쇄는 100% 서버 소유
  - → 서버가 거부해도 이펙트만 제거하면 되므로 상태 불일치 없음

### 6.2 블록 리플리케이션 (최대 리스크)
- ❌ 전체 배열 리플리케이트 — 절대 금지
- ✅ **시드 전송 + 파괴 이벤트만 Multicast** (파괴 1회당 3~4바이트)
- 재접속 불가 → 중간 상태 복원 로직 불필요

### 6.3 세션
| 항목 | 결정 |
|---|---|
| 세션/로비 | EOS (스팀 배포 시에도 사용 가능 — 스팀 계정으로 EOS Connect 인증 가능) |
| 인증 | Device ID 익명 (개발 속도 우선) |
| 방 | 공개방 목록 존재 |
| 시작 | 전원 준비 → 방장이 시작 |
| 난입 | 없음 |
| 종료 | 로비 복귀 |
| 저장 | 전적/진행도 저장 없음 |

> 📌 스팀 배포 시 EOS 재배포 설치 프로그램을 프리퀴짓으로 포함해야 함 (에픽 스토어 배포판은 런처에 내장되어 불필요)

### 6.4 성능
- **서버 틱레이트 30Hz** (그리드 기반이라 픽셀 정밀도 불필요)
- 캐릭터 위치 갱신은 **거리 기반 조절** (`NetCullDistanceSquared` + 우선순위)

## 7. 최적화 설계

### 7.1 블록 렌더링
**HISM(인스턴스드 스태틱 메시) + 표면 추출**
- 논리 데이터(3D 배열)와 렌더링을 **완전 분리**
  - 서버: 배열만 들고 판정 (1바이트 × 27,000칸 = 27KB, 무시 가능)
  - 클라: 배열 보고 인스턴스 생성
- **표면 블록만 인스턴스화** — 산 내부에 파묻힌 블록은 영원히 안 보임. 보통 전체의 20~40%
- 파괴 시: 인스턴스 제거 + **주변 6칸만 재검사**해서 새로 노출된 블록 추가 → 갱신 비용 최대 6

| 맵 규모 | 총 블록 | 실제 렌더링(추정) |
|---|---|---|
| 21×21×8 | ~3,500 | ~1,000 |
| 31×31×12 | ~11,500 | ~3,500 |
| 41×41×16 | ~27,000 | ~8,000 |

→ 부족하면 **그리디 메싱**으로 승격 (렌더링 레이어만 교체 가능한 구조로 설계)

### 7.2 충돌
**하이브리드**
- 캐릭터 이동 → HISM 컬리전 + CharacterMovementComponent (클라 예측 유지)
- 폭발·낙하 판정 → 그리드 배열 조회 (O(1), 블록 수와 무관)

### 7.3 이펙트
- **오브젝트 풀링** — 폭탄·물줄기·파편·아이템 전부. 미리 100~200개 확보 후 재사용
  - 최대 부하 추정: 8인 × 폭탄 5개 × 6방향 × 범위 3 ≈ 물줄기 세그먼트 700개
- **연쇄 폭발 프레임 분산** — 단계당 0.05~0.1초 딜레이
  - 서버 스파이크 제거 + "촤르륵" 퍼지는 연출 동시 획득

### 7.4 원칙 (인지 항목)
- 머티리얼 인스턴스 사용, **동적 머티리얼 생성 금지**
- 반투명 가림 처리 트레이스는 **0.1초 간격** 또는 카메라 이동 시에만
- 사운드 Concurrency로 **동종 사운드 최대 4~5개** 제한
- **데디 서버 빌드에서 나이아가라·사운드·머티리얼이 돌지 않는지 반드시 확인**
- ⭐ `stat unit` / `stat game` / `net profile`을 **1주차부터 켜고 개발**. "다 만들고 최적화"는 3주 프로젝트에 존재하지 않음

### 7.5 튜닝 값은 전부 데이터로 노출
DataAsset 또는 GameMode 변수: 폭탄 타이머, 폭발 범위, 잔존 시간, 갇힘 지속, 서든데스 시작 시각, 바닥 파괴 여부, 아이템 드랍률

## 9. 테스트 & 인프라

- **개발은 로컬, 주 1회 VPS 실환경 검증**
  - ⚠️ 로컬만으로 개발하다 막판에 VPS 올리면 지연 관련 문제가 한꺼번에 터짐
- **VPS 사양**: 2코어 / 4GB RAM 정도면 충분 (월 $5~12 구간)
- **비용 절약**: Vultr·DigitalOcean·Linode는 시간당 과금 → 테스트할 때만 켜기
  - 주 1회 2~3시간 × 3주 = **실제 청구액 1~2달러 수준**
- **리전**: 도쿄 (국내 핑 30~50ms). 미국 리전으로 고지연 테스트 1회 권장
- AWS 프리티어(t2.micro, 1GB RAM)는 UE 데디 서버에 빠듯 — 비추

## 10. 미결정 항목 (개발하며 확정)

- 그리드 한 칸 크기 / 캐릭터 이동 속도 → **1주차에 몸으로 결정**
- 서든데스 시작 시각, 매치 최대 길이
- 아이템 최대 스택 상한 (폭탄 개수·범위)
- 스폰 무적 시간 유무
- 갇힌 채로 미세 이동하다 구멍에 빠지는 상황 — 살릴지(자업자득) 막을지
- 바닥 블록 파괴 허용 여부
- 데모 배포 방식 (itch.io 무료 배포 등)

## 11. 리스크 정리

| 리스크 | 심각도 | 대응 |
|---|---|---|
| 절차 맵 생성 튜닝에 시간 소진 | 높음 | 폴백 맵 우선 제작, 검증 함수 분리, 3주차 배치 |
| 지형 변형 리플리케이션 | 높음 | 시드 + 이벤트 방식으로 이미 구조적 해결 |
