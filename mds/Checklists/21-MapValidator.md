## 코드 검증 (정적)
- [x] 전부 **static 순수 함수** — 그리드 수정 없음. 액터·월드·룰셋을 모른다.

- [x] **정수 연산·TArray만** (불변식 4) — 방향 배열 상수 순서, 방문 표시 `TArray<bool>`,
      큐는 `TArray`. `TSet`/`TMap` 순회·float 비교 없음.
      판정이 흔들리면 같은 시드가 실행마다 통과/리롤이 갈려 재현이 깨진다
- [x] 임계값을 `FThresholds` 로 노출 (하드코딩 없음 — 호출부가 룰셋에서 넘긴다)

## 이동 규칙 (게임 규칙 그 자체)
- [x] **1칸은 오르고 2칸은 못 오른다** (CLAUDE.md 확정값). 상수를 2로 두면 검증은 통과하는데
      실제로는 못 올라가는 맵이 생산된다 — 테스트 ①에 "2칸 실패" 케이스를 명시적으로 넣었다
- [x] 낙하는 높이 제한 없음
- [x] 이웃 기둥은 **위에서 내려오다 처음 만난 발판에서 멈춘다** — 계속 훑으면 벽 안쪽 공간까지
      도달 가능으로 세어 ④(고립 구역)가 무력해진다
- [x] "설 수 있는 칸" = 그 칸이 비었고 **바로 아래가 solid** (GDD 2.1 "발판만이 안전하다")

## ④ 의 예외 — 외곽 링 제외 (되풀이 방지)
- [x] **최외곽 링은 ④ 검사에서 제외한다.** 경계 벽 꼭대기는 "설 수 있는 칸"이면서 도달 불가인데
      그건 버그가 아니라 **설계**다 — 벽을 2층으로 올린 이유가 1칸 점프로 벽 위에 못 올라가게
      하려는 것이었다(`FallbackMapGenerator` 2단계 주석). 제외하지 않으면 **정상 맵이 전부
      ④에서 떨어져 리롤이 무한히 돈다.** 첫 구현에서 실제로 폴백 맵이 불통과했다

## 동작 검증 — 자동화 (2026-08-06 · **전체 20스위트 실패 0** 직접 실행)
`CrazyArcade3D.MapGen.MapValidator` — 검사별 통과/실패 쌍:

| 검사 | 통과 케이스 | 실패 케이스 |
|---|---|---|
| ⓪ IsStandable | 바닥 위 공중 칸 | 발판 없는 공중 · 블록 안 · z=0 · 범위 밖 |
| ① 연결성 | 평지 · **1칸 점프로만 닿는 2층** | **2칸 높이** · 벽으로 갈린 두 구역 |
| ② 최소 거리 | 맨해튼 16 ≥ 8 | 맨해튼 2 < 8 |
| ③ 탈출로 | 사방이 트인 스폰(4방향) | 3방향 봉쇄(1방향만) · 공중에 뜬 스폰 |
| ④ 고립 구역 | 트인 맵 | 사방이 높이 2 벽으로 밀봉된 방 |
| ⑤ 아이템 균등 | 사분면에 2개씩 | 한 사분면에 9개 |

- [x] ⑥ `Validate` 종합 — 빈 스폰/빈 그리드 거부 + 실패 사유 문자열이 비어 있지 않음
- [x] ⑦ **`FallbackMapGenerator` 출력이 `Validate` 전체 통과** — 실측: 스폰 8개 /
      스폰 간 최소 맨해튼 **9** / 아이템 18개. 기본 임계값 `SpawnMinManhattan = 8` 은
      이 실측치에 근거한다(여유 1). 폴백이 불통과면 절차 생성기의 리롤이 영원히 돌고
      증상은 "가끔 맵 로딩이 멈춘다"로 나타나 원인 찾기가 매우 어렵다 — 여기가 방어선이다
- [x] ⑧ 결정론 — 5회 반복 시 BFS 방문 집합 완전 동일
