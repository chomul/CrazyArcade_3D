# Checklist 33 — 갇힌 상대 밀어서 터뜨리기 (+ 봇이 노린다)

> 2026-08-10 사용자 확정. 원작 크레이지 아케이드의 규칙.
> 회귀 스위트: `CrazyArcade3D.Gameplay.TrappedPop` · `CrazyArcade3D.AI.BotPopTrapped`

## 확정 규칙
- [x] 물방울에 갇힌(`Trapped`) 캐릭터를 **갇히지 않은 `Alive`** 캐릭터가 몸으로 밀면 **즉시 사망**
- [x] 갇힌 사람끼리는 서로 못 터뜨린다 · 시체도 못 터뜨린다 · 자기 자신 제외
- [x] 팀 개념 없음(라스트맨 스탠딩) — 자기 자신만 아니면 누구든
- [x] 유예·경고 없음 (원작이 그렇다)
- [x] **봇도 노린다** (2026-08-10 추가 확정). 우려를 전달했음에도 사용자가 넣는 쪽으로 결정 —
      "갇히는 순간이 거의 사형선고가 된다(봇 여럿이 동시에 달려온다)". 실측이 그대로 나왔다(아래)

## 접촉 판정 — 공식을 새로 만들지 않았다
- [x] **캐릭터끼리는 `Block` 이라 오버랩 이벤트가 오지 않는다** (`ACharacter` 캡슐 = `Pawn` 프로필,
      `BaseEngine.ini` 의 Pawn 프로필에 Pawn 채널 오버라이드가 없어 기본 `ECR_Block`).
      그래서 `ABomb::CanKickInto` 가 "폭탄을 막는 플레이어" 를 찾는 것과 같은 액터 순회를 쓴다
- [x] `ACA3DCharacter::GetContactReach()` 로 **킥과 같은 함수·같은 룰셋 값**
      (`BombKickReachToleranceCells`)을 쓴다. 기존 킥의 인라인 계산도 이 함수 호출로 교체했다 —
      공식이 두 벌이면 "킥은 되는데 터뜨리기는 안 되는 거리" 가 생긴다
- [x] 수평 78cm(34+34+10) · 수직 186cm — 위층 사람이 평면상 겹쳤다고 터지지 않게
- [x] 입력 방향은 보지 않는다 (순수 거리) — "지나가다 닿으면 봇도 사람과 똑같이" 와 방향 조건은
      양립하지 않고, 확정 규칙에도 방향이 없다

## 매 틱 비용 — 검사 주체를 "갇힌 쪽" 으로 뒤집었다
- [x] 터뜨리는 쪽에 두면 살아 있는 8명이 매 틱 "갇힌 사람 있나" 를 전수 조사한다.
      갇힌 쪽에 두면 `LifeState != Trapped` 한 줄에서 되돌아간다 —
      **평상시 총비용 = 캐릭터당 enum 비교 1회**
- [x] 봇도 같은 구조: 갇힌 적이 없으면 **BFS 를 돌리기 전에** 끝난다.
      거리 프리필터는 수평 맨해튼(= 실제 걸음 수의 하한이라 갈 수 있는 목표를 잘못 버리지 않는다)

## 경합 — 전부 코드로 확인
| 항목 | 결과 |
|---|---|
| 니들 탈출 | 팝 검사가 캐시가 아니라 `LifeState` 를 **매번** 읽는다 → 탈출이 먼저 돌면 그 틱에 Alive 로 보여 "탈출한 뒤 죽는" 일이 없다 |
| 익사 타이머 | `ServerKill` 이 `ClearTimer(TrappedTimer)` 를 부르고, 발화해도 Dead 가드에서 되돌아간다 |
| 동시 다중 접촉 | 검사가 희생자 1인 기준이라 첫 일치에서 return. `ServerKill` 중복은 Dead 가드, `NotifyPlayerDeath` 는 `AddUnique` + 가드라 `PendingDeaths` 와 어긋나지 않는다 |
| 갇힘 이동·점프 | **무수정** (`TrappedMoveSpeed` · `DoJump` 의 Trapped 금지). 회귀 테스트로 고정 |
| 데디 | `IsRunningDedicatedServer()` 가드 **없음** — 사망은 시각이 아니다 |

## 봇 FSM
- [x] 우선순위 **Evade > PopTrapped > (설치) > Attack > Wander**
- [x] 설치보다 위인 근거: ① **갇힌 상대에게 폭탄은 효과가 없다**(`ServerTrap` 이 Alive 가 아니면
      무시 — 물줄기를 또 맞아도 갇힘이 안 늘어난다) 반면 접촉은 확정 킬 ② 설치 분기는 성공 즉시
      `Evade` 로 전이해 목표에서 멀어진다 ③ 갇힘 수명 4초 vs 설치 쿨다운 2초 — 한 주기 미루면 놓친다
- [x] **위험 회피는 그대로 최상위**. `PlanPopTrapped` 의 `IsPassable` 이 `!DangerCells.Contains` 라
      **위험 셀을 지나는 경로 자체를 만들지 않는다**
- [x] 목표 셀 = 상대의 **발밑 셀 그 자체**. 옆 칸 중심이면 중심 거리 100cm 라 사거리 78cm 에 못 미쳐
      "도착했는데 안 터진다" 가 된다. 상대 칸을 목표로 두면 캡슐 Block 으로 68cm 앞에서 막히고
      그 순간 접촉이 성립한다 (도착이 목적이 아니라 접촉이 목적이다)
- [x] 목표 상실(탈출·사망·도달 불가)은 **매 틱** 확인 — 재계획 주기 0.4초를 기다리지 않는다
- [x] 결정론: 목표 집합 1회 BFS, 확장 순서는 `VoxelMove::PlanarDirs` 고정. 스폰 순서를 뒤집어도
      같은 하나를 고른다(테스트)

## 룰셋 추가
| 이름 | 기본값 | 근거 |
|---|---|---|
| `bPopTrappedOnContact` | true | 기능 on/off |
| `BotPopTrappedMaxCells` | 16 | `TrappedDuration 4초 × MoveSpeed 4칸/초` = **물리적 최대치**. 그보다 먼 목표는 도착 전에 물방울이 끝난다. 즉 기본값이 상한이고, 이 노브는 나중에 **줄이기 위한** 손잡이다. 직선이 아니라 실제 걸음 수로 잰다 |

`EDeathCause` 에 `None`·`Popped` 추가. `Popped` 를 따로 둔 이유: 사인 집계에서 "익사" 와
"밀려서 터짐" 이 섞이면 나중에 못 가른다. 소비처 전수 확인 — switch 없음·복제 없음·UI 없음.
